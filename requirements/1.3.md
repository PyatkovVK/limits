# Version 1.3 requirements

These are the agreed requirements for Limits 1.3 (`1.3.0` in the application), including the follow-up decision about Windows time formatting. Feature and requirements PRs target `1.3-demo`; the release PR is [#25](https://github.com/PyatkovVK/limits/pull/25), from `1.3-demo` to `main`. Integration into the demo branch does not publish a release.

## Scope and traceability

| Item | Required result | Requirements | Implementation PR |
| --- | --- | --- | --- |
| 1. Linux runtime | Installed AppImage/DEB works without separately installing Codex. Include the pinned native executable and license; fail packaging if the target runtime is unavailable. The shared packager also supplies macOS. | [LIN-INST-006](linux/installation.md), [MAC-INST-006](macos/installation.md) | [#19](https://github.com/PyatkovVK/limits/pull/19) |
| 2. Linux sign-in | Open the validated sign-in URL in the default browser from both a desktop launch and AppImage. Preserve the desktop session, remove private AppImage runtime paths, use a launcher fallback, and make failures retryable without exposing OAuth data. The reported screenshot's missing-runtime prerequisite is covered by item 1. | [LIN-INST-007/008](linux/installation.md), [COM-ACC-001/009/010](common/accounts/codex.md), [COM-DATA-008/009](common/privacy.md) | [#20](https://github.com/PyatkovVK/limits/pull/20) |
| 3. Monitoring without an open Codex app | Keep server ownership, quota polling, and credential refresh in common for all three operating systems. Sign-in, restart, reconnect, and resume work while the Codex desktop app and VS Code are closed. This does not claim full isolation of the default account's existing credential/configuration store. | [COM-ACC-014/015 and the separate future COM-ACC-013](common/accounts/codex.md) | [#21](https://github.com/PyatkovVK/limits/pull/21) |
| 4. Windows weekly time | Show `7д` / `7d` with a weekly countdown. At least one day uses `5д20ч` / `5d20h`; below one day use `16:39`. Update from the server timestamp each second and when selection changes, with clear unknown/expired states and no layout overflow. | [WIN-WDG-001/016/017](windows/widget.md) | [#22](https://github.com/PyatkovVK/limits/pull/22) |
| 5. Windows outside click | Hide details when focus leaves the app, preserve native dialog operations, and leave the panel hidden during polling/movement. | [WIN-UI-008/009](windows/panel-and-tray.md), [COM-UI-023/026](common/interface.md) | [#23](https://github.com/PyatkovVK/limits/pull/23) |
| 6. macOS browser handoff | Show a localized notice for about 1.2 seconds, collapse the expanded notch, then open browser sign-in. Cover account addition from Settings and browsers that do not take focus; guard cancellation and display-mode changes. | [MAC-NOTCH-012/013](macos/notch.md) | [#24](https://github.com/PyatkovVK/limits/pull/24) |

## Acceptance checks before release

| Area | Acceptance check |
| --- | --- |
| Clean packaged installation | Test Linux x64 AppImage/DEB and both macOS architectures without a separately installed Codex/VS Code/Node.js. Verify the matching bundled executable, license, native helpers, and executable permissions. Missing runtime files must fail the build. |
| Linux browser handoff | Launch from the desktop and AppImage in the target graphical session; verify default-browser opening and a successful callback. Simulate missing/failing launchers, confirm a safe error and unlocked retry, and verify that OAuth URLs do not enter diagnostics. |
| Independent monitoring on Windows/macOS/Linux | Sign in through Limits, fully quit Codex and VS Code, observe fresh server samples, suspend/resume, restart Limits, and exercise server reconnection. Confirm that failed initial credential reads retry and routine polls do not force repeated token rotation. |
| Weekly countdown | Check RU/EN with more than a day (`5д20ч` / `5d20h`), exactly a day, less than a day (`16:39`), missing/invalid timestamps, and expiry. Switch accounts/buckets; inspect 200, 210, 220, 240, 280, 320, and 400 px layouts. Percentages must remain server-provided. |
| Windows dismissal | Open details from the widget and tray, focus another application, and confirm dismissal. Poll or move the widget and confirm it stays hidden. Open/cancel/fail the native background picker, then confirm normal outside-focus dismissal is restored. |
| Physical MacBook notch | Add an account from both the expanded panel and Settings. Confirm the visible notice, timed collapse before browser opening, successful sign-in with no browser-focus change, cancellation during the wait, and mode switching without collapsing a new notch session. |

Automated tests and Windows demo smoke support these checks. They do not substitute for native Linux/macOS package builds or acceptance testing on a Mac with a physical notch. Keep the release PR in draft until integration and release validation are complete; merge and delete feature branches only after their changes are preserved in `1.3-demo`.
